# Nehal Agarwal — Medical Portfolio (MERN)

A full-stack medical portfolio and lightweight CMS for **Nehal Agarwal**, final-year MBBS student
at Government Medical College, Chittorgarh — built with MongoDB, Express, React and Node.js.

Same architecture as the reference portfolio (`karan-portfolio`), re-skinned and re-written for a
**medical / data / clinical** audience: clinical postings, research interests, medical writing,
health education, community health and target career roles.

## Features

- Responsive React portfolio with dark + light theme, preloader, animated timeline and typed roles
- Filtered sections for Clinical, Research, Writing, Health Education, Community Health, Education,
  Leadership, Volunteering, Programs, Awards, Certifications, Media, Projects and Roles
- Expandable entries with supporting proof (images / PDFs / links)
- Search + "show more" pagination
- JWT-protected admin dashboard (hidden from the navigation — open it with `/admin`)
- Edit profile/hero, stats, profile cards, skills, interests, portfolio entries, journey timeline and section copy
- Contact form with a built-in message inbox in the admin panel
- Upload up to four images/PDFs per request (8 MB each)
- MongoDB persistence through Mongoose
- Local JSON fallback for development when `MONGODB_URI` is absent
- Express serves the production React build

## Development

```bash
npm install
npm run dev
```

- React/Vite: `http://localhost:5173`
- Express API: `http://localhost:5000`

Vite proxies `/api` and `/uploads` to Express.

## Administrator login

Production credentials live in `.env` (gitignored) and are seeded on first start:

- URL: append `/admin` to the site address — e.g. `http://localhost:5173/admin`
- Username: `nehal`
- Password: `Nehal@2026`

The password is stored as a **bcrypt hash** after the first change. Both the
username (login ID) and password can be changed from inside the panel:
**Admin → Settings → "Change admin password" / "Change admin username (login ID)"**
(each requires the current password). Change them after the first sign-in.

Security already in place: login lockout after 5 failed attempts (15 min),
JWT sessions (8 h), `/admin` and `/api` blocked in `robots.txt`, security
headers on every response.

## Content policy — actual data only

Every entry on the site traces back to Nehal's own LinkedIn profile (headline, about,
experience, education activities, skills, services, open-to-work, recommendation) or to
contact details she supplied. Nothing is invented. Where her own profile is ambiguous
(e.g. rank "2nd" in experience vs "first" in about), a `CONFIRM:` note marks it inside
the entry so it can be corrected from the admin panel.

Run this to print every open item before sharing the site:

```bash
python3 scripts/list_todos.py
```

See `NEHAL-CHECKLIST.md` for the full source-map (what came from where) and the list of
speculative v1 content that was removed.

## MongoDB and production configuration

Copy `.env.example` to `.env` and set:

```env
PORT=5000
MONGODB_URI=mongodb+srv://...
JWT_SECRET=a-long-random-secret
ADMIN_USERNAME=your-admin-name
ADMIN_PASSWORD=a-strong-password
CLIENT_ORIGIN=https://your-domain.example
```

`ADMIN_PASSWORD` may also contain a bcrypt hash beginning with `$2`.

Build and run:

```bash
npm run build
npm start
```

Express serves `client/dist` after the production build.

## Important deployment notes

- Use MongoDB Atlas or another MongoDB deployment for production — free hosts have an ephemeral
  filesystem, so JSON edits and uploads are lost on redeploy.
- Replace the demo JWT secret and administrator password.
- Put uploaded media in Cloudinary, S3 or another object store (set the `CLOUDINARY_*` env vars).
- Restrict `CLIENT_ORIGIN` to the deployed frontend origin.

See `DEPLOY-GUIDE.md` for the full Render / Railway walkthrough and

## Rebuilding the seed content

The portfolio content is generated by a script, so it can be regenerated or adjusted in bulk:

```bash
python3 scripts/build_content.py     # rewrites server/data/db.json
```

> Note: once Nehal edits content through the admin panel with MongoDB connected, the database copy
> wins — the script only reseeds `server/data/db.json`.
